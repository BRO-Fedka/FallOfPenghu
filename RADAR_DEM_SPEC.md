# Карта высот для радарного режима — требования к поставке

Документ для агента, который готовит реальные данные карты. Приёмник — игровой рантайм Fall of Penghu. Файл нужен **только радарному режиму** (горизонтали на суше). Обычный вид карты DEM не читает.

Координаты те же, что у `penghu_map_v1`: плоскость EPSG:3825, локальные метры, без геодезии в рантайме.

---

## 1. Зачем

В радаре суша чёрная. Поверх неё нужны топографические линии — изогипси реальной высоты острова (перепады рельефа), не декоративный шум.

Архипелаг Пэнху низкий (высшая точка порядка 50 м). Слишком грубый DEM даст 1–2 линии или ложные ступени. Слишком шумный — «лапшу» вокруг берега.

---

## 2. Что сдать

В каталог карты игры, рядом с `piers_field.npz` и geojson:

```text
penghu_map_v1/dem.npz
```

Опционально рядом положить исходный GeoTIFF для проверки (`dem_src.tif`) — игра его не читает.

Не сдавать: тайлы XYZ, WGS84 GeoJSON с высотами в вершинах, hillshade PNG, контуры уже нарезанные «на глаз», SRTM без обрезки океана.

---

## 3. Система координат

Совпадает с `penghu_map_v1/manifest.json`. Не изобретать второй origin.

| Поле | Значение |
|---|---|
| CRS растра | EPSG:3825 |
| Единицы XY | метры |
| Ось X | easting, на восток |
| Ось Y | northing, на север |
| Координаты в `frame` | **локальные**: EPSG:3825 минус `origin_epsg3825` из манифеста |
| Origin | `[303629.30711733666, 2596980.7306913873]` (текущий пакет v1) |

`frame = [minx, miny, maxx, maxy]` в тех же числах, что `bbox_penghu` / geojson (порядка 10⁴ м, не 2.6e6).

Строка 0 массива — **юг** (`miny`), столбец 0 — **запад** (`minx`). Это совпадает с GL-текстурой игры (`uv.y = 0` у южного края). Если исходный GeoTIFF north-up, перед записью npz строки перевернуть.

Не класть lon/lat, Web Mercator, TWD97 в градусах.

---

## 4. Покрытие и разрешение

Минимум: `bbox_penghu` из манифеста плюс пад **2 км** со всех сторон (чтобы горизонтали не обрезались у берега).

```text
minx, miny, maxx, maxy ≈
  -21502, -31972, 20595, 34653   плюс 2000 м
```

Желательно: вся рамка мира 200×200 км (`frame_min_xy` … `frame_max_xy`), чтобы Тайвань в кадре тоже имел рельеф. Если тяжело — сначала только Penghu, Тайвань можно вторым файлом позже; тогда в манифесте явно написать покрытие.

Разрешение клетки:

| | |
|---|---|
| Цель | **10 м** (предпочтительно) |
| Допустимо | 5–20 м |
| Не принимать | ≥ 30 м как основной слой (SRTM 1″ на таком плоском архипелаге почти бесполезен) |

Размер при 10 м на bbox Penghu с падом: примерно 4500×6900 клеток, float32 ≈ 120 МБ сырой, npz сжатый ожидаемо сильно меньше. Если файл > ~40 МБ сжатый — резать покрытие или шаг 20 м, не 30 м.

Пиксели квадратные. `cell_m` один на весь растр. Без пирамиды внутри npz.

---

## 5. Высоты

- Значение пикселя: метры над уровнем моря, **float32**.
- Вертикальный датум: предпочтительно **TWVD2001** или EGM96, как у исходника Taiwan MOI / Copernicus. Записать имя датума в манифест. Не смешивать эллипсоидальные высоты GPS с ортометрическими без пометки.
- Суша: реальная высота, включая значения около 0…2 м на низких намывах.
- **Океан и лагуны вне берегового полигона: nodata**, не `0`. Ноль на воде даст ложную горизонталь 0 м вдоль всего моря и дубль береговой линии (берег у игры уже векторный).
- Nodata: `-1000` (поле `nodata` в npz). Не NaN в int-растре; в float32 NaN допустим **дополнительно**, но `-1000` обязателен как канон.
- Клип по `coast.geojson`: всё, что вне суши Penghu (и вне Тайваня, если покрытие шире), должно быть nodata. Не оставлять «берег SRTM», он не совпадёт с OSM-контуром.
- Не сглаживать сильнее 1–2 клеток. Не поднимать сушу искусственно.

Ожидаемый диапазон на Penghu: примерно 0…60 м. Если max < 15 м или max > 200 м на архипелаге — проверить проекцию и единицы (футы, дециметры).

---

## 6. Формат `dem.npz`

Ключи:

```text
height     float32, shape (H, W)     # H = rows = north-south, W = cols
frame      float64, shape (4,)       # minx, miny, maxx, maxy в локальных метрах
cell_m     float64, scalar           # размер клетки, м; должен ≈ (maxx-minx)/(W-1)
nodata     float32, scalar           # канон: -1000
vertical   unicode, optional         # "TWVD2001" | "EGM96" | ...
source     unicode, optional         # имя датасета и дата снимка
```

`np.savez_compressed`. Совпадает по духу с `piers_field.npz`: один раз обработали, лежит в git с игрой.

Проверка геопривязки (обязательна перед сдачей):

1. `cell_m` согласован с `frame` и `(W, H)` в пределах 1%.
2. Точка Magong Harbor ≈ локальные (3766, 9102) попадает в растр; высота там конечная, не nodata, и разумная (несколько метров, не 400).
3. Пиксель в 5 км западнее западного берега — nodata.
4. `origin_epsg3825` в сопроводительном тексте совпадает с манифестом карты. Если origin сменится — пересчитать `frame`, не оставлять старый сдвиг.

---

## 7. Источники (рекомендация агенту данных)

По убыванию пригодности для Пэнху:

1. DEM Тайваня (MOI / NLSC, 20 м или лучше, TWD97 / EPSG:3825 нативный).
2. Copernicus GLO-30, перепроецированный в EPSG:3825, затем маска по `coast.geojson`.
3. ALOS AW3D30 — запасной, не первый выбор.

Не использовать как основной: SRTM 30 м, ASTER GDEM, bathymetry GEBCO (это не суша).

Перепроекция: bilinear или cubic на высотах, **nearest** на маске суша/вода. Маску строить из игрового `coast.geojson`, не из берега датасета.

---

## 8. Чего игра не просит на этом шаге

- Векторных горизонталей (GeoJSON isolines). Игра снимет изогипси с растра сама, шаг **5 м**.
- Hillshade, slope, aspect.
- Батиметрии для сетки океана: сетка радара — геометрическая 1 км, не изобаты.
- Нескольких LOD-растров.

Если позже понадобится радиогоризонт ПВО, тот же `dem.npz` должен годиться без второй поставки.

---

## 9. Манифест

Добавить в `penghu_map_v1/manifest.json`:

```json
"layers": {
  "dem": {
    "file": "dem.npz",
    "width": 4521,
    "height": 6913,
    "cell_m": 10.0,
    "nodata": -1000,
    "vertical": "TWVD2001",
    "coverage": "penghu_pad_2km"
  }
}
```

Числа — фактические после экспорта. Пока файла нет, ключ `dem` не писать: игра трактует отсутствие файла как «горизонталей нет».

---

## 10. Приёмка

Пакет принимается, если:

- `dem.npz` читается `numpy.load`, ключи из §6 на месте;
- CRS и origin совпадают с картой;
- океан — nodata, суша внутри `coast.geojson` почти вся с валидной высотой;
- визуально 5-метровые изолинии ложатся на острова, а не на море, и не повторяют береговой контур сплошной линией 0 м.

Пакет не принимается: WGS84, абсолютные 3825 в `frame`, нули на всём океане, клетка ≥ 30 м как единственный слой, сдвиг origin.
