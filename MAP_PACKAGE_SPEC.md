# Поставка карты в игру — требования к упаковке

Документ для агента карты. Приёмник — игровой рантайм Fall of Penghu (pygame-ce). Геометрия уже в плоскости. Кривизну Земли, геодезию, ортодромии и «метры по эллипсоиду» не считать и в файл не класть. Все длины, площади и попадания в игре — евклидовы метры на плоскости EPSG:3825.

Итог: один пакет, который можно положить в репозиторий игры и загрузить без GIS-стека.

---

## 1. Что сдавать

Каталог или zip:

```text
penghu_map/
  manifest.json
  taiwan.geojson
  coast.geojson
  vegetation.geojson
  buildings.geojson
  roads.geojson
  airports.geojson
```

Имя пакета версии: `penghu_map_v1`. Смена содержимого слоёв — bump `content_version` в манифесте и при необходимости имени папки.

Не сдавать: Shapefile, GeoPackage, растры, DEM, ортофото, розовые дороги, пиксельные зоны, контуры aerodrome, хотспот-JSON, отладочные PNG, промежуточные кэши пайплайна.

## 2. Система координат

| Поле | Значение |
|---|---|
| CRS | EPSG:3825 |
| Единицы | метры |
| Ось X | easting, на восток |
| Ось Y | northing, **на север** (плюс Y = север) |
| Расстояния | √(Δx²+Δy²), плоскость |
| Высота | не входит в xy; если позже понадобится для симуляции — отдельный файл, не этот пакет |

Рамка мира: квадрат 200 000 × 200 000 м вокруг архипелага. В манифесте указать:

- `frame_min_xy`, `frame_max_xy` — абсолютные easting/northing EPSG:3825 углов рамки;
- `origin_xy` — точка вычитания для локальных координат (центр рамки);
- `bbox_penghu`, `bbox_taiwan` — осевые bbox слоёв в **локальных** метрах.

**Координаты во всех geojson — локальные:** `(easting - origin_x, northing - origin_y)`. Игра не должна видеть числа вида 2.6e6. Origin один на весь пакет. Не смешивать абсолютные и локальные координаты в геометрии.

GeoJSON по спецификации OGC — WGS84. Здесь это **не** WGS84. В манифесте явно: `"coordinates": "EPSG:3825_local_meters"`. Не перепроецировать в lon/lat «для совместимости».

Замыкание полигона: первое и последнее кольцо совпадают (классический GeoJSON). Без самопересечений, без NaN/Inf.

## 3. `manifest.json`

Обязательные поля:

```json
{
  "format": "fall-of-penghu-map",
  "format_version": 1,
  "content_version": "1.0.0",
  "crs": "EPSG:3825",
  "units": "m",
  "y_axis": "northing_up",
  "coordinates": "EPSG:3825_local_meters",
  "origin_xy": [0.0, 0.0],
  "origin_epsg3825": [123456.0, 2600000.0],
  "frame_min_xy": [-100000.0, -100000.0],
  "frame_max_xy": [100000.0, 100000.0],
  "sea": "background_not_polygon",
  "layers": {
    "taiwan": { "file": "taiwan.geojson", "features": 1, "vertices": 717 },
    "coast": { "file": "coast.geojson", "features": 121, "holes": 0 },
    "vegetation": { "file": "vegetation.geojson", "features": 292, "variant": "F", "hash": "9fa777810c3a" },
    "buildings": { "file": "buildings.geojson", "features": 11099, "osm": 3601, "modeled": 7498, "overlaps_dropped": 0 },
    "roads": { "file": "roads.geojson", "features": 1476 },
    "airports": { "file": "airports.geojson", "icao": ["RCQC", "RCCM", "RCWA"] }
  },
  "excluded": ["pink_roads", "pixelated_zones", "aerodrome_boundaries", "dem", "orthophoto"],
  "notes": "Taiwan clipped by world frame; do not draw when viewport is Penghu-only."
}
```

Числа `features` / `vertices` — фактические после экспорта, не копия старой выжимки. `origin_epsg3825` и `origin_xy` в примере — схема; подставить реальные.

Кодировка UTF-8, без BOM, перевод строк LF. JSON компактный или indent=2 — не важно, валидный RFC 8259.

## 4. Слои и свойства

Каждый файл — `FeatureCollection`. `properties` только из списка ниже. Лишние OSM-теги не тащить (name, wikidata, полный dump). Геометрия: Polygon / MultiPolygon / LineString / MultiLineString. Point не нужен.

### `taiwan.geojson`

- 1 Polygon (допустим MultiPolygon, если обрезка дала куски — тогда перечислить в манифесте).
- Упрощение ε = 100 м уже применено.
- Обрезан рамкой и замкнут стороной квадрата.
- Свойства: `id` (строка).

Игра рисует слой, только если bbox пересекает кадр. Не считать слой глобальным фоном.

### `coast.geojson`

- Берег Penghu, 121 остров, без дыр.
- Один остров = один Polygon (одно внешнее кольцо).
- Свойства: `id` (стабильный), `area_m2` (float), `inhabited` (bool, если известно; иначе опустить).
- Полная геометрия, без ε по LOD.

### `vegetation.geojson`

- Variant F: лес (класс 10) и трава; пашня уже влита в траву.
- Полости залиты, дыр нет.
- Свойства: `id`, `class` (`forest` | `grass`), `area_m2`.
- Хеш пайплайна в манифесте.

### `buildings.geojson`

- Один слой. OSM и модель уже слиты. При пересечении контуров OSM оставлен, модель выброшена.
- Свойства:
  - `id` (стабильный, уникальный в файле);
  - `source`: `osm` | `modeled`;
  - `kind`: короткий класс или `null`. Допустимые: `hospital`, `school`, `government`, `transport`, `religion`, `industrial`, `residential`, `unknown`. Не выдумывать слой складов;
  - `floors`: int или `null`;
  - `height_m`: float или `null` (если нет — игра может взять `floors * 2.5`);
  - `rect`: `true`, если ровно 4 вершины без учёта замыкающей точки (модельные дома).
- Складов, портов и «стратегических» объектов отдельным флагом нет. Вместимость не писать.

### `roads.geojson`

- LineString или MultiLineString. Не полигоны.
- Мосты **в этом же файле**, не отдельно.
- Свойства:
  - `id`;
  - `highway`: класс OSM (`residential`, `secondary`, `tertiary`, …);
  - `lanes`: int;
  - `width_m`: float (уже разрешённый OSM width или дефолт класса);
  - `bridge`: bool;
  - `on_small_island`: bool (остров < 3 км²).
- В пакет только учтённая сеть (ожидаемо ~1476). Тропы, footway, path, тупиковый service на больших островах не включать.

### `airports.geojson`

- Только рисуемые части: runway, strip, apron, taxiway, parking.
- Свойства: `id`, `icao` (`RCQC` | `RCCM` | `RCWA`), `apt_kind` (`runway` | `strip` | `apron` | `taxiway` | `parking`).
- 4 контура aerodrome и 415 пиксельных зон не включать.

## 5. Чего не класть в этот пакет

- Растровые тайлы и пирамиды.
- Нарезку сеткой 1 км.
- Несколько LOD-файлов берега (ε=250, 120, …). Упрощение — задача игры или отдельный опциональный кэш, не поставка v1.
- WGS84, градусы, `lat`/`lon` в геометрии.
- Высоты вершин и TIN в geojson. Растр высот — отдельный файл по `RADAR_DEM_SPEC.md`, не внутри слоёв геометрии.
- Дубли OSM+модель.
- Диагностические слои.

---

## 6. Контроль качества перед передачей

1. `manifest.json` читается, все `file` существуют.
2. Счётчики манифеста совпадают с числом feature.
3. Все координаты конечные, в пределах рамки с запасом (Тайвань может касаться края рамки).
4. Полигоны замкнуты, берег и зелень без дыр.
5. Нет розовых дорог и excluded-слоёв.
6. Локальный origin: bbox Penghu не обязан быть около (0,0), но числа должны быть порядка 10⁵ м, не 10⁶.
7. Короткий `CHECKSUMS.txt` (SHA-256 на каждый файл) — желательно.

Передавать пакет целиком в репозиторий игры или одним zip. Дальше геометрию трогает игровой агент: загрузка, LOD, индекс, отрисовка.

---

## 7. Минимальный контракт API для загрузчика

После распаковки игра должна уметь:

- прочитать origin и переводить экран ↔ метры без повторной проекции;
- итерировать слои независимо;
- узнать `bridge` и `width_m` у дороги;
- отличить `rect` здание для `draw.rect`;
- отключить `taiwan` по пересечению bbox с кадром.

Если формат нарушен (WGS84, абсолютные 3825 в geojson, дыры в береге, два слоя зданий) — пакет не принимается, правит агент карты.
